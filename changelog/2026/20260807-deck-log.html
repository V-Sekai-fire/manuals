V-Sekai Multiplayer Fabric Deck Log — 2026-08-07 (Friday)

Date: 2026-08-07

Archived six repositories that the Fly.io move of rfd/0089 left without a consumer, and resynchronized the organization inventory in rfd/0062 to the real organization. The inventory had drifted far enough to name ten repositories by names they no longer carry, to list five repositories that left the organization, and to omit about thirty that exist.

The sweep also surfaced one inconsistency that no record explains: zone-server-h2o is archived on GitHub while rfd/0094 names it the host of the minimum user-generated-content game loop.

Added

  • RFD 2069, which archives the self-host-era support repositories and the empty stubs: fabric-container-verify, the rfd/0056 quadlet verification queue, whose every target rfd/0089 already archived; fabric-casync-central, which never carried content; fabric-scoop-central, the scoop bucket for the Windows demo of the parked godot-loop-slice; fabric-platform-central, the rfd/0065 Burrito and casync packaging path; and the two empty placeholders vulkan-video-godot and steamdeck. Each one is tombstoned rather than deleted, so its history stays reachable.
  • A record of the fabric-platform-central risk in that RFD’s DETAILS.md. rfd/0090 describes a live Burrito release of uro on Fly.io, and rfd/0065 puts that packaging in the archived repository. One API call reverses the archive if the deploy still reads from it.
  • A Moved to V-Sekai-archive section in the rfd/0062 inventory, for the three repositories that left this organization: lean-predictive-bvh, viser, and usd-converter-for-vrchat.
  • Counts in the inventory: 72 repositories, 48 active and 24 archived.

Changed

  • The rfd/0062 inventory now uses current repository names, per rfd/0064. GitHub keeps a redirect after a rename, so every old name still resolved and hid the drift. godot is fabric-godot-core, merge is fabric-godot-assembly, observability is fabric-game-observability, manuals is multiplayer-fabric-manuals, and the five *-image repositories are the *-quadlet repositories. rfd/0105’s DETAILS.md carries the full mapping.
  • The inventory’s repository sections follow the current stack: an engine and client area, a zone host and guests area for rfd/0094’s composition, a backend and data area for the FoundationDB work of rfd/0103, one hexagon-cores area holding both the canonical hexagons and the standalone Lean workspaces, and a content flow and authoring area.
  • The archived table now carries a Basis column naming the decision that retired each repository, and lists all 24 rather than 3.

Removed

  • The inventory’s service-images section. Every repository it listed is archived by rfd/0089, which supersedes rfd/0061’s quadlet deployment target.

Split the archive out

Created multiplayer-fabric-archive and moved every retired record there, per RFD 206a: the 26 rejected and superseded MADR records under _archive/decisions/, the image they cite, and the two superseded RFDs, rfd/0011 on the observability stack and rfd/0061 on the deployment target. The new repository carries the manuals history up to the split, so each moved file keeps every commit that touched it at its original path. It holds plain Markdown, with no site and no checks.

Both superseded RFDs used to render as current. A reader who opened either one read a dead design with no marking on the page.

Repairing the inbound links was the work a move forces, because a deleted file with no stub leaves a 404 on the site. Four relative links in the 2026-06-06 deck log, two pointers in rfd/0071, and one reference each in rfd/0089, rfd/0060, rfd/0070, and the rfd/0062 inventory now point at the archive repository. _quarto.yml drops the decisions/attachments resource.

The move also exposed a link that never resolved. Two archived records cite the debug-orb image relative to _archive/decisions/, and the image sat two directories away in decisions/attachments/. Quarto skips _archive, so no rendered page ever exercised it. The archive repository puts the image where the existing links expect it.

Fixed

  • The asset-citation guidance named references.bib, a file the repository no longer carries. The bibliography converted to CFF, and pages/references.qmd renders the 94 entries under references: in CITATION.cff through cffconvert. AGENTS.md and rfd/0013 now name CITATION.cff. The changelog entries that describe references.bib stay as they are, because they record what was true on their own date.
  • The site config pointed at the pre-rename repository. site-url read .../github.io/manuals and repo-url read .../v-sekai-multiplayer-fabric/manuals, while the site publishes at .../multiplayer-fabric-manuals/, so every edit-this-page link and the feed URL resolved to the wrong place. Both now name the current repository, as do the three gh api .../rulesets commands in rfd/0021.

The zone tier, recorded

zone-server-h2o was archived and is unarchived again. It is the host repository, and RFD 206b records the tier around it: h2o as HTTP ingress and reverse proxy, Janet as the dynamic layer for routing glue and configuration, libtaskweft as a C library holding HTN search and game state, and Godot as the client over GDExtension. Janet loads the C core as a native module. Rust is out, so the core is C.

FoundationDB stays the store, through libfdb_c. rfd/0075 stands and rfd/0006’s CockroachDB does not describe this tier, so the FDB record set stays in force: rfd/0002, rfd/0073, rfd/0074, rfd/0084, rfd/0097, and rfd/0103. ecto_foundationdb and ecto-bench-tpcc keep a live consumer.

The record states its own gaps rather than guessing past them. The startup, memory and speed claims for this tier are not measured, and data/measurements/ holds nothing for Janet or a C taskweft core. Four questions stay open: which part drives the libfdb_c callbacks, where Elixir and zone-backend sit, whether Janet replaces the libriscv guest runtime, and which part terminates a WebTransport session.

The guest boundary, recorded

RFD 206c makes a simulation guest a local shared object loaded over the plain C ABI, and h2o routes to it with no network hop. The CDN keeps one job, which is bulk asset delivery, and it no longer delivers guest programs for simulation.

Fan-out runs inside the tick. One publish ring per zone, one writer, and many readers holding cursors. The 100-byte packet of rfd/0053 is serialized once and fanned out as a pointer and a refcount, so N subscribers cost one serialization rather than N. A cross-loop delivery takes one batched wakeup per tick, which caps a loop near 64 wakeups per second at 64 Hz.

FoundationDB stays off that path. rfd/0097 measured a watch fire at 12115.1 us, which is most of a 15.6 ms tick, against 8.9 us for an AF_UNIX round trip. The watch probe also failed at exactly 10000 watches with error 1032, and a watch is edge-triggered, so it loses values between the fire and the re-read. The tick owns the libfdb_c callback chain of rfd/0073 and appends the durable log off-tick.

The record states the cost of local mode rather than hiding it. A local .so shares the zone’s address space, so a guest fault takes the zone down. rfd/0083 chose Fil-C for memory safety and rfd/0095 built two guest classes for the same reason, and local mode has neither property. That suits first-party simulation code and does not suit user-generated code, so rfd/0094’s UGC loop needs its own record.

RFD 206c closes two of RFD 206b’s four open questions, which are the database path owner and the guest boundary. Two stay open and one arrives: where Elixir and zone-backend sit, which part terminates a WebTransport session, and how a UGC guest runs.

Two tiers, with FoundationDB as the store

RFD 206d names egress as the cost that binds, and the store as the cost that does not. Bandwidth per client sets the bill, and one node serves the database load. No deployment runs, so the record carries no cost figure.

The tier count drops to two. Godot is the client, holding rendering, XR, IK, and local physics. Elixir and Phoenix form the server, holding identity, the room directory, and the presence relay. The server relays presence rather than simulating it, so Phoenix supplies the identity and sessions that a Godot server would need written in GDScript.

The store stays FoundationDB, through ecto_foundationdb, so rfd/0075 stands. The record accepts rfd/0103’s limits rather than working around them: no joins, no or, no aggregates in the database, and one Between clause per query. That trade holds because the relational need is analytical, and the analytical half runs on zstd Parquet and DuckDB as data/measurements/ already does. OLTP access is point lookups by player and room identity.

Twelve stores are recorded with their outcome. TiDB, YDB, and Apache Ignite are viable and not chosen, and the record says why for each. TiDB is the one that keeps relational form with no adapter work, at the cost of more processes and MySQL’s weaker constraint set. Rust was banned and then unbanned during the search, which returned TiDB to the list. Rivet 2.0 is Apache 2.0 and ships a TypeScript SDK, with no Elixir or Godot client.

taskweft stays an Elixir NIF, which V-Sekai-fire/multiplayer-fabric-taskweft already is, so Janet and the C libtaskweft are dropped.

rfd/0107 and rfd/0108 are marked abandoned and carry a pointer to this record. Their measurements stay valid, and the back-pressure rule of rfd/0108 still applies to any relay.

Five questions stay open on record: player-hosted zones against server-hosted, interest management as the only lever on the 256 kbps figure, server authority that a relay cannot give, whether the Godot WebTransport client speaks to a Phoenix endpoint, and how many FoundationDB processes run and where.

The zone becomes one pinned Godot build, hosted as a Rivet actor

RFD 206e makes a zone a child process under Rivet’s container-runner, one process per room. The child is the engine at tag v2026.06.27.1907-multiplayer-fabric, which resolves to commit 2cecde75 and reports Godot 4.7.0 beta. That tag’s modules/ already carries sandbox for libriscv guests, http3 for WebTransport, multiplayer_fabric and multiplayer_fabric_asset for the zone, xr_grid for presence, and openxr with webxr for XR. So one build is the client, the zone server, and the guest host.

A C child of h2o plus libriscv stays possible and is not built. Its only advantage is memory per process, and that figure is unmeasured. No resonance module appears at the tag, so rfd/0022’s spatial audio needs checking before anyone relies on it.

One process per room deletes work rather than adding it. rfd/0072, rfd/0082, and rfd/0086 become unnecessary, because each exists only to hold many zones in one process. rfd/0080 narrows to one room’s entities. A guest fault kills one room rather than every room, which is what rfd/0095 wanted from Bubblewrap.

The actor input is four optional CBOR fields, read from container-runner/src/input.rs: command, args, env, and port. The decoded input is also the actor’s persisted state, so a woken actor restores the same launch spec, and unknown fields are ignored rather than rejected. A room’s scene and its tuning therefore travel in the actor input, and no zone-side registry is needed.

The transport is settled by the runner’s source rather than by its documentation. container-runner is TCP-only. src/proxy.rs forwards to http://127.0.0.1:{child_port} and the ws:// form, src/child.rs checks readiness with TcpStream::connect((Ipv4Addr::LOCALHOST, child_port)), and no udp, quic, http3, or h2 appears in the runner source. TCP_NODELAY does not appear either, so Nagle is unmitigated there.

The answer is two sockets in one child. A TCP port satisfies Rivet’s contract and carries the control plane. A UDP port carries game traffic outside Rivet’s tunnel, with the engine’s http3 picoquic module on it. Rivet never touches the pose stream, so rfd/0008, rfd/0023, rfd/0049, rfd/0058, and rfd/0088 all stand. The cost is that Rivet’s gateway does not route the UDP port, so a zone directory must publish the host and port, which makes the Uro role required rather than optional.
