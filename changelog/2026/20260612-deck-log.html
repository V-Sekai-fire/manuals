V-Sekai Multiplayer Fabric Deck Log — 2026-06-12 (Friday)

Date: 2026-06-12

Recorded the instanced loot-action core-loop slice as MADRs: the product scope and the performance gate, the five hexagons, and the core architecture around Lean kernels lowered to SPIR-V over r128 fixed-point.

Added

  • Product and process decisions: MVP vertical slice, first-party content budgets, genre-generic naming, CASSIE desktop authoring, and a merged build via the editor MCP.
  • Hexagon decisions (core, ports, adapters): combat, loot, progression, budgeter, and presence, the last wrapping the existing presence decisions.
  • Core architecture decisions: Lean kernel cores with flat-C adapters, Lean to Slang to SPIR-V codegen, r128 fixed-point as a Lean library, the pure-reducer byte-state contract, deterministic state, server authority with deferred rollback, sandboxed RISC-V behavior, the forward renderer, and the webtransportd transport adapter.

Added (the steel thread, later the same day)

  • The merged multiplayer-fabric assembly builds: the linux double-precision editor (23 branches, zero conflicts) and the Android arm64 double template (android_release.apk), per the toolchain decision.
  • Wire parity under server authority in the merged build: loot (256 rolls), combat (88 effects), and four-player contention (64 rounds, 4 concurrent clients) all match their Lean golden vectors; headless OpenXR initializes against Monado per the Monado decision.
  • New repos: loot, combat, progression (each a core/ports/adapters triad with Plausible-pinned golden vectors), and fabric-verify (the smokes as a quadlet queue, per the queue decision).
  • The r128 chain: the Lean R128 matches the vendored r128.c (8,200 vectors x 7 ops), the uint32-limb R128L matches R128 (50,000 sweep), and the lean-slang-emitted SPIR-V kernel matches r128.c on the GPU (4,096 multiplies), per the r128 Lean library decision.
  • lean-slang runs on Lean 4.30 (V-Sekai-fire/lean-slang#1).

Fixed

  • merge gitassembly drops the dead feat/spatial-audio-server ref (merge#36), so the canonical assembly runs again.
  • The http3 listener findings are recorded as a decision: one listener per process, reply routing to a single session, and a teardown double free, with the loop’s interim shape until the module fixes land.

Fixed (later still)

  • The http3 multi-session reply routing and teardown double free, as godot#56 — the fix pattern comes from the webtransportd single-pending-slot bug (fire/webtransportd@f0fc9a4). Post-fix, four concurrent clients each receive their own winner announcements and the server survives teardown; the quadlet four-player smoke verifies per client.

Added (replication and deployment)

  • The entity-transform wire is integral: int64 absolute micrometers (no origin shift), velocity tied to the predictive BVH’s V_MAX, a 42-byte payload, and a Lean+Plausible source-of-truth in entity_packet (decision, godot#58).
  • Fabric channels are reliability classes with control in the packet payload (decision).
  • The MCP runtime bridge drives the deployed OpenXR build over adb (decision, vsekai-godot-mcp#1).
  • New repos: the standalone Lean workspaces loot-core, combat-core, progression-core, and the playable loop-slice.

Fixed (WebTransport multi-session stability)

  • The picoquic WebTransport server survives four or more concurrent sessions and completes full rounds, on feat/module-http3. Reliable traffic rides one persistent framed stream per session instead of a fresh stream per message, which exhausts stream credit and starves the connect handshake (decision). Five supporting fixes hold the network thread up under load: a mutex on the inbound queue, an inclusive wake-loop that drains and services receive on every callback, get_packet_peer peeking the queue front per the MultiplayerPeer contract, a connection table sized for the fanout, and the picoquic textlog gated behind the verbose flag.
  • The queue race and the wake-loop starvation each carry a Lean+Plausible proof in the new http3-queue workspace: the locked queue stays size-honest for every schedule, the inclusive loop stays starvation-free, and the models exhibit the schedules the unlocked and exclusive variants fail.

Added (the loop on both transports and OpenXR)

  • The loop chooses its transport at launch through TRANSPORT: ENet for the local slice, WebTransport for the browser and headset paths, with the text protocol unchanged across both. Control rides reliable on channel 0, the high-rate transform rides unreliable on channel 1.
  • An OpenXR client joins the four-player loop over LAN as a real player: it autoconnects to the desktop server, fights in immersive OpenXR above the frame floor, and the round commits progression. The headset controllers drive the loop through polled, edge-detected actions (left thumbstick locomotion, right trigger attack, right A grab, left Y teleport vote), reading the bool action trigger_click rather than a float trigger, with the XR camera held by reference so the locomotion branch runs.
  • The merge assembler returns to the base branch and drops the local assembly branch on every run, including dry runs and failures, so a half-built assembly leaves the checkout clean.
